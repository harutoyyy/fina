**5. データ構造**

**5.1 銀行口座の種別**

普通預金、定期預金、社会保険積立（仮想口座）、消費税積立（仮想口座）の4種別。各社に実口座＋仮想2口座（社保積立・消費税積立）を自動付与する。

**5.2 勘定科目（3階層構造）**

大項目（PL区分）: 販管費 / 製造原価 / 営業外費用 / 営業外収益 / 特別 など。科目マスタで必須とし、表示順を持つ。

|            |               |
|------------|---------------|
| **名称**   | **収入/支出** |
| 売上高     | 収入          |
| 売上原価   | 支出          |
| 販売管理費 | 支出          |
| 営業外収益 | 収入          |
| 営業外費用 | 支出          |
| その他費用 | 支出          |

中項目（勘定科目）: 一般的な科目＋自社追加分で管理する（例：通信費、地代家賃、支払手数料、外注費、法定福利費など）。取引先にはデフォルト科目として中項目＋小項目（小項目は任意）を設定できる。

区分（固定/変動/臨時）は科目ではなく取引属性として管理し、翌月自動生成ルールに使用する。

小項目（補助科目）: 中項目配下の任意項目。例：水道光熱費→電気/ガス/水道、通信費→携帯/インターネット、地代家賃→Aアパート/Bアパート 等。

確定条件: 中項目は確定時必須。小項目は任意（未入力の場合は警告表示し、後から管理者が整備できる）。

**5.3 取引データ**

※取引種別「振替」＝同一会社内の口座間移動（資金移動）や仮想口座への積立/取崩など、外部取引を伴わない内部振替を指す。

|            |                                   |
|------------|-----------------------------------|
| **項目**   | **内容**                          |
| 取引種別   | 経費/売上/原価支払/給与/借入/振替 |
| 取引日     | 実際の入出金日（現金主義のキー）  |
| 計上月     | YYYY-MM                           |
| 金額       | 収入は正の値、支出は負の値        |
| 摘要       | 取引の説明                        |
| 支払方法   | 振込/引落                         |
| 確定フラグ | 予定/確定の区別                   |

**5.4 取引の親子構造**

親（トランザクション）は通帳に出る1回の動き。子（明細）は請求書単位、控除（源泉税など）、案件単位、科目単位。親の金額は子明細合計で自動算出する。

**5.5 口座残高**

口座＋年月の組み合わせで管理。期首残高・期末残高を保持する。

**5.6 取引先**

種別：請求先/支払先/双方

**5.7 給与区分**

会社ごとに区分名（例：工事部門、営業部門）を設定。コスト種別は販管費または原価。紐づく中項目と支払日を持つ。登録済み23区分（全12社分）。

**6.2 売上入力**

【確定事項（追記）】

・売上は「請求（予定入金）」と「入金実績（分割可）」と「控除内訳」を親子構造で保持する。資金繰り表には予定（請求金額）と実績（入金実績合計）を保持し、差額は売上サマリで表示する。

・確定は2段階：①請求確定（入力者可、確定日時・確定者を記録。解除は管理者のみ）②入金・控除確定（管理者のみ）。

・未整合チェック：差額（請求−実入金合計）と控除合計が一致しない場合はアラート表示。全額入金完了前は警告、全額入金完了後はエラー（入金・控除確定不可）。許容差額なし（0円一致）。

・分割入金：入金実績を複数行で登録し、資金繰り表の出納行は入金実績（実出納日）として複数行に分かれて良い。差額（控除）は入金行ごとではなく請求サマリで確認する。

**6.3 原価支払入力**

【確定事項（追記）】

・原価は「計上額（控除前：集計用）」と「振込額（資金繰り反映）」を保持する。資金繰り表へは振込額のみ反映する。

・控除内訳はカテゴリ明細（複数行）として保持し、PL集計対象とする。控除カテゴリは固定（管理者のみ追加）、明細は入力者が複数行入力可。

・確定フロー：入力者は準備完了まで、確定は管理者のみ。分割支払中（未払残が残る状態）は確定不可。支払完了後、差額（計上額−実支払合計）と控除合計が一致しない場合は確定不可。

・証憑添付は原価入力では必須としない（別システムで管理）。

**6.4 給与入力**

【確定事項（追記）】

・個人単位の管理は行わず、会社別の「給与グループ」単位で合計入力する。給与グループは会社ごとのマスタで管理し、区分（原価/販管/外注）を固定で持つ。0円行も保持可能。

・取込は「合計入力専用テンプレ（Excel）」で実施し、支給月（YYYY-MM）をキーとする。テンプレ行は「会社×支給月×給与グループ」。

・給与グループ（親）には支給日（必須）、課税支給、交通費、諸経費、総支給（自動計算）、控除（項目別＋内容行）、差引支給（自動計算）、人数を保持する。

・支払内訳（子）：出金日（実出納日）、支払方法（振込/引落/現金引出）、出金口座、金額を複数行で保持する。支給日と出金日が異なって良い。資金繰り表には支払内訳単位で出金行を生成する。

・整合チェック（必須一致）：①総支給−控除合計＝差引支給 ②差引支給＝支払内訳合計（振込＋現金引出）。

・確定フロー：給与入力者は準備完了まで、確定は「給与管理者ロール」が実施。確定日時ログを保持。確定解除は管理者のみ。

・自動計算/自動反映：課税支給金額を基礎に「社会保険積立（15%）」と「消費税積立（10%）」を自動計算（入力時点で表示）。準備完了時点で原価支払一覧/積立（仮想口座）へ自動反映し、確定前は変更に追随更新する。

・給与担当者向けビューと管理者向けビューを権限で出し分け、積立計算等の管理者専用項目は給与担当者ビューでは非表示（または簡易表示）とする。

会社→給与区分を選択して入力。一括登録（全件アトミック処理）。

**支給項目**

支給金額、法定福利費見積(自動15%)、消費税見積(自動10%)、繰越金調整、交通費、立替経費

**控除項目**

**集計表示**

**7.2 表示・操作**

月×口座単位で保存。日付をまたいで自由移動可能（日付自体は変更しない、見た目のみ変更）。複数行まとめて移動可能。並び替え時、残高は即時再計算する。

**7.3 予定→実績**

予定値と実績値を保持。差額を±表示。金額変更時のみ更新日を更新する。

**7.4 繰り延べ機能**

7.5 印刷・検索・フィルター

・印刷は「全体印刷（会社×口座×月）」と「部分印刷（選択範囲）」を提供する。

・全体印刷：A4横/A3縦を選択可能。列のON/OFF、拡大縮小、口座ごと改ページ。ヘッダに期首残高/当月入金合計/当月支払合計/月末残高を表示。親のみ/親＋子明細を選択可能（子列：取引先・金額・科目・摘要）。

・部分印刷：資金移動証憑用テンプレと任意抜粋テンプレを提供。取消行はデフォルト印刷対象外。

・検索/フィルター：Ctrl+F相当の表内検索（非表示列も対象）を提供。列ヘッダの▼でフィルター可能。対象日付は実出納日/予定日を切替。取引先（部分一致）、金額帯、空欄抽出（取引先/科目）、取消表示切替。フィルター条件は会社内共有も可能。フィルター結果をそのまま印刷可能。

7.6 現金引出（親子明細）・金種表

・複数の現金支払（給与等）をまとめて現金引出する「現金引出バッチ」を資金繰り表から作成できる。親＝通帳の現金引出1回、子＝用途明細。リンクが基本だが手入力用途も可。

・確定条件（厳格）：親引出金額＝子用途合計、かつ金種表合計＝引出金額。確定は管理者のみ。

・金種表：子明細ごとに金種内訳を保持でき、最小枚数優先で全金種（1円〜1万円）を用いてぴったり一致する自動提案を行う。給与等は手入力で上書き可。用途一覧と金種表は別々に印刷可。

・引出日（実出納日）と用途支払予定日は異なって良い。資金繰り表上の実支払日は引出日でよい（運用上、引出と支払を同日扱い）。

資金繰り表から「翌月へ繰り延べ」が可能。元データの予定日を変更し、当月から消え翌月へ表示する。

**8. 資金移動ロジック**

**8.1 会社間資金移動**

入力時に相手会社へ自動生成。双方向リンク。修正・削除は連動する。

**8.2 同一会社内資金移動（A→B）**

経費入力時に自社支払口座＝Bを選択。「原資の資金移動を作成する」チェックで資金移動元口座（デフォルト＝メインA）と資金移動日を入力。金額＝支払明細合計。

A口座には資金移動1本を表示し、展開すると紐づく支払明細を参照表示。B口座には実際の支払明細を表示。明細データは二重保持しない（参照表示）。

**9. 定期支払テンプレート機能**

**9.1 頻度設定**

毎月、隔月（偶数/奇数指定可）、四半期、年次、特定月（複数月指定）、任意開始月指定。

**9.2 金額設定**

固定、変動（前回コピー）、手入力。

**9.3 月初一括生成**

未確定で生成。期限超過は赤表示。支払漏れ検知一覧を表示する。

**10. 借入管理**

**10.1 契約管理**

借入金額、実行日、返済方式（元金均等/据置/一括）、金利タイプ（固定/変動）、金利改定履歴保持、返済頻度（月次/四半期等）、前払/後払、返済日指定（25日/27日等）。

**10.2 スケジュール生成**

元金/利息/残高を自動生成。金利改定時に再計算可能。資金繰りへ未確定で反映。元金/利息は別明細で計上する。

**11. リース管理**

契約単位で管理。支払総額のみ。月初生成で資金繰りに反映する。

マスタ設計（画面・権限）

取引先マスタ

• 取引先タグは必須。内部キーは固定（顧客/協力会社/経費/銀行/グループ会社/その他）とし、表示名は管理者が任意に変更可能（例：顧客→元請/親会社）。

• 権限により候補を絞り込み表示（売上担当は顧客中心、経費担当は経費中心、管理者は全件）。タブ増殖は避ける。

• 振込先口座は複数登録可。必須：銀行/支店コード、種別、口座番号、名義カナ（半角）。口座は無効化（利用停止）で履歴保持。

• グループ会社間取引は取引先タグ「グループ会社」を用いて表現（同一取引先マスタ内）。

契約/地点テンプレ（取引先配下、任意）

• 地点（物件）単位で定期生成設定を保持（家賃/水道光熱/通信等で利用）。入力しない取引も多いため必須ではない。

• 周期は毎月/隔月（奇数・偶数）/四半期/指定月に初期対応。予定日ルール（月末/任意日）＋休日調整（前営業日/次営業日/なし）を持つ。

• 担当者割当はテンプレに任意で保持。未設定時は会社担当へフォールバック。経費確定BOXの表示対象制御に用いる。

科目マスタ

• 大項目（PL区分：販管費/原価/営業外等）は必須。中項目（勘定科目）・小項目（補助科目）を持つ。小項目は確定時も任意。

• 表示順は必須。削除は原則不可（未使用のみ削除可）。使用済みは利用停止（非アクティブ）で運用。

• 固定/変動/臨時は科目ではなく取引属性として扱う（区分は子明細単位、資金移動明細には付与しない）。

• 取引先デフォルトは中項目＋小項目（小が無い場合は中のみ）を保持。

控除カテゴリマスタ（売上・原価）

• 売上用と原価用でマスタは分離（カテゴリ名称は別）。デフォルト科目（中/小任意）への紐づけは必須。未設定でも準備完了は可、確定は不可。

• 控除入力は一覧の見た目を維持しつつ、行の展開/サイドパネルで内訳を縦に複数行入力（横長回避）。摘要は任意。証憑（支払通知書等）は任意で添付可能。

• 前倒し入金・保留金はカテゴリ内に小項目（発生/相殺）を持ち、必須入力。金額は常に正で入力し、符号（±）は小項目により自動決定。月次で発生/相殺を別集計できる。

• 値引/値上（端数調整含む）はカテゴリとして保持し、符号を扱える（端数調整は必要に応じてプラス/マイナス）。

• 親会社の控除内訳は直近の入力月を探索して『項目のみ（カテゴリ/小項目/摘要）』を次月以降へ自動生成。金額・証憑はコピーしない。

口座マスタ

• 会社×口座で管理。メイン口座は原則1つ。支払口座は複数可。表示順必須。無効化（新規候補から除外、過去閲覧可）と、非表示（普段の候補から除外）を持つ。

• 口座の役割は複数選択可・未選択可。デフォルト役割を用意し、表示名変更・追加・利用停止が可能（内部キー固定＋追加は自社キー）。

• 仮想口座（社会保険積立/消費税積立）は会社ごとに持つ。通常は非表示、必要時のみ表示。

• FB出力設定（口座×用途：総合振込/給与/賞与）を口座詳細に保持。依頼人コード/委託者コード等は基本任意で、必要な口座・用途のみ必須化できる。

給与グループマスタ

• 会社ごとに給与グループを保持。区分（原価/販管/外注）はグループに固定で持つ。0円行は『前月実績あり→当月0円表示、2ヶ月連続0円→デフォ非表示』。

• 支給日は自由に設定（日付指定 or 月末）し、休日調整（前営業日/次営業日）を持つ。

• 支払内訳は毎月入力するが、振込/現金引出のデフォルト口座（提案値）はグループに保持できる。

• 控除セット（よくある控除項目）をグループに任意で保持可能。グループは既存からコピー作成できる。

売上入力（入金予定）

• 確定は2段階：①請求確定（入力者可、日時/確定者記録、解除は管理者のみ）②入金・控除確定（管理者のみ）。

• 分割入金は入金実績（複数行）として保持。資金繰り表の入金行ごとの差額は表示せず、請求サマリで『未入金残』『差額（請求−実入金合計）』『控除合計』を表示する。

• 未整合（差額≠控除合計）は確定不可。許容差額なし。分割入金中は警告のみで、全額入金完了後はエラー（確定不可）。

原価支払入力（下請支払）

• 親に計上額（控除前）と振込額（実支払）を保持。資金繰り表には振込額のみ反映。

• 控除内訳はカテゴリ明細として保持し、確定条件は『全額支払完了後、差額（計上−実支払合計）と控除合計が一致』。分割支払中は確定不可。

• 入力者は準備完了まで、管理者が確定。証憑添付は必須にしない（別システム前提）。

給与入力

• 取込方式：合計入力専用テンプレ（Excel）。キーは会社×支給月×給与グループ。個人明細は管理対象外。

• 控除は項目マスタ＋内容行（複数）。科目紐づけ未設定は警告/未整合として管理し、管理者側で整備する。

• 支払内訳（出金イベント）は複数行で保持：出金日（資金繰り表の実出納日）、支払方法（振込/引落/現金引出）、出金口座、金額。支給日（親）は別に保持。

• 整合チェック：①総支給−控除合計＝差引支給 ②差引支給＝支払内訳合計。未一致は準備完了不可。

• 社保積立（課税支給×15%）・消費税積立（課税支給×10%）を自動計算。給与が準備完了になった時点で自動反映し、確定前は追随更新。計算基礎は課税支給金額で固定。

• 入力者向けと管理者向けで表示ビューを分離（15%/10%等、集計用項目は管理者ビュー中心）。

現金引出（親子明細＋金種表）

• 資金繰り表から複数行を選択して現金引出バッチを作成（親＝引出、子＝用途明細）。リンクが基本、手入力用途も可。

• 親引出金額＝子合計、金種表合計＝引出金額は一致必須（厳格）。確定は管理者のみ。

• 金種表は必須。子明細ごとに金種内訳を自動提案（全金種、最小枚数優先、金額ぴったり）。給与等は手入力で上書き可。用途一覧と金種表は別印刷可。

• 現金引出の実出納日は引出日。用途の予定日（支払日）とは異なってよい。

振込（手数料・FB出力）

• 銀行/支店マスタは初期同梱。ゆうちょ等も対応。コードは検索選択。

• 手数料は出金口座ごとに管理。本支店/他支店/他行、金額帯等を初期から対応。例外は明細単位で上書き可。

• FB出力は『確認済』バッチのみ。FB出力後は編集不可で取消→再作成のみ（取消権限は管理者のみ）。

• 振込済は明細単位で管理。全明細振込済でバッチ完了。振込済後は原則編集不可（取消は管理者のみ）。

借入・リース

• 借入は返済表の自動計算を必須。対象：元金均等、据置（利息のみ）あり、期日一括、周期（四半期/半年/社債等）。元利均等は初期対象外。

• 契約入力：実行日、返済開始日、返済日ルール＋休日調整、頻度、回数/完済予定、金利（固定/変動）＋金利変更履歴、利息前払/後払、日割基準（365/360）、端数処理（利息は四捨五入デフォ）、元金端数調整（初回/最終回、契約で選択）。

• 金利変更時の再計算は未確定将来分のみ。返済表の再生成（更新）は管理者のみ。

• 資金繰り表へは元金返済と利息を別行で反映。残高一覧（任意時点の残高）が出せる。

• リースは単純スケジュール（利息計算なし）。契約単位で月額・期間・回数・支払日ルール・休日調整。端数は初回/最終回で調整。

### 認証（Better Auth）
- NextAuth.js → Better Auth に移行済み。セッション管理はDB方式。

### DB設計方針
- Prisma ORM + PostgreSQL (Neon)
- マルチテナント：1DB内に全12社、company_id で分離
- 金額：BigInt（円単位、小数点なし）、収入=正値、支出=負値
- マスタは物理削除しない（isActive=false で無効化）
- 監査ログ：Prisma Middleware で自動記録
