## 1. 本ドキュメントの位置づけ

PWDX 側との連携設計を進めるために、fina 側で「**何のために / どんなデータを / どう取りたいか**」を先にまとめ、PWDX 側に「これ取れる？」と確認する**質問票**として使う。

### 構成

| 章 | 内容 | 主な読み手 |
|---|---|---|
| §4 ユースケース | fina で PWDX 連携を使う業務シナリオ | fina 側 / PWDX 側 |
| §5 データ項目チェックシート | 各ユースケースに必要なデータ項目を埋める表 | **PWDX 側に埋めてもらう** |
| §6 技術仕様質問一覧 | API 形式・認証・権限など技術的な確認事項 | **PWDX 側に答えてもらう** |
| §7 進め方 | PWDX 側との対話の手順 | 両者 |

### 想定する使い方

```
1. fina 側でこのドキュメントを完成させる（PWDX 側への質問が整った状態）
2. PWDX 側に提示し、§5 のチェックボックスと §6 の回答欄を埋めてもらう
3. 回答を見てギャップ分析
4. 取れない項目は「妥協 / 代替 / PWDX 側追加実装の依頼」に仕分け
5. 合意できた範囲で詳細設計（別ドキュメント）に進む
```

## 3. 想定する連携の全体像

```
┌────────────┐     ┌────────────┐     ┌────────────┐
│   PWDX     │     │   fina     │     │  弥生会計   │
│ 鳶部門の    │     │  経理・    │     │  仕訳・     │
│ 案件管理    │ ──> │  資金繰り   │ ──> │  決算      │
│ 請求発行    │     │  取引管理   │     │            │
└────────────┘     └────────────┘     └────────────┘
       ↑                  │
       └──────────────────┘
       入金消込結果の通知（一部）
```

**役割分担:**

| データ | 正本 | fina での扱い |
|---|---|---|
| 案件・請求書・発注 | PWDX | PWDX から取得 |
| 取引先マスタ | PWDX | PWDX から取得・キャッシュ |
| 社員 | PWDX | PWDX から取得（給与照合用） |
| 認証（ユーザー ID） | PWDX (Keycloak) | OIDC で同期 |
| 会社マスタ（経理視点） | fina | fina 独自（PWDX 連携時は PWDX から初期化） |
| 銀行口座・勘定科目 | fina | fina 独自 |
| 取引データ・資金繰り | fina | fina 独自 |

## 4. ユースケース一覧

各ユースケースには優先度（Must / Should / Could）を付ける。

| ID | 名前 | 概要 | 優先度 |
|---|---|---|---|
| UC-01 | 請求書 → 売上の自動投入 | PWDX で発行された請求書を fina の売上行として自動計上 | **Must** |
| UC-02 | 取引先マスタの参照 | PWDX の取引先を fina の取引先プルダウンに反映 | **Must** |
| UC-03 | 発注 → 原価支払の自動投入 | PWDX で確定した発注を fina の原価支払予定として記録 | Should |
| UC-04 | 案件マスタの参照 | PWDX の案件 ID と名前を fina の取引行のメモで参照 | Could |
| UC-05 | 社員マスタの参照（給与照合） | PWDX の社員情報を fina の給与入力時に参照 | Could |
| UC-06 | 入金消込結果のフィードバック | fina で入金消込が完了したら PWDX 側に通知し、案件ステータスを更新 | Should |
| UC-07 | SSO（PWDX のログインで fina にも入る） | Keycloak Realm `pwdx` を fina の認証 IdP として使う | **Must** |
| UC-08 | 会社申請時の PWDX 認証取得 | 公開申請フォームで PWDX 認証し、会社情報を pre-fill | **Must** |
| UC-09 | 証憑・契約書への参照リンク | PWDX 内の PDF への URL を fina の取引行から開けるようにする | Could |

### UC-01: 請求書 → 売上の自動投入

```
[アクター]
  PWDX のユーザー（営業）
  fina の自動取込ジョブ
  fina のユーザー（経理）

[前提]
  会社対会社の連携が確立（PwdxIntegration.enabled=true）
  「請求書 → 売上」同期が ON

[基本フロー]
  1. PWDX で a 会社の営業が請求書を発行（PWDX 内で確定）
  2. PWDX が Webhook を発火 or fina が定時にポーリング
  3. fina が PWDX API から請求書データを取得
  4. fina の Transaction (type=SALES, status=未確定) として登録
  5. 二重投入防止のため externalRef (PWDX 請求書 ID) で冪等チェック
  6. 経理担当が fina の資金繰り表で確認 → 確定

[例外フロー]
  - 同じ請求書 ID が既に取込済 → 上書き or スキップ（要決定）
  - PWDX 側で請求書が取消 → fina の該当行も「取消」ステータスに変更
  - 取引先が fina の取引先マスタに無い → 自動作成 or 取込保留
```

### UC-02: 取引先マスタの参照

```
[基本フロー]
  1. fina が PWDX API から取引先一覧を取得（日次バッチ）
  2. fina の TradingPartner テーブルに upsert
     - externalSource = "pwdx"
     - externalId = PWDX の取引先 ID
  3. 既存の PWDX 由来取引先は更新、新規は追加
  4. PWDX 側で削除（または非アクティブ化）されたものは fina で isActive=false
```

### UC-03: 発注 → 原価支払の自動投入

```
[基本フロー]
  1. PWDX で発注が「確定」状態になる
  2. fina が PWDX API から発注データを取得
  3. fina の Transaction (type=COST_PAYMENT, status=未確定) として登録
  4. 支払予定日を資金繰り表に反映
  5. 経理担当が確認 → 確定
```

### UC-04: 案件マスタの参照

```
[基本フロー]
  1. fina が PWDX API から案件一覧を取得（日次バッチ or 必要時）
  2. fina の Project テーブル（新規モデル）に upsert
  3. 取引行（Transaction）のメモに案件 ID を紐付け
  4. fina 内で「この案件の取引一覧」が見られる
```

### UC-05: 社員マスタの参照（給与照合）

```
[基本フロー]
  1. fina の給与入力時、所属社員一覧が必要
  2. PWDX API から社員リストを取得
  3. fina の Employee テーブル（新規モデル）に upsert
  4. 給与計算時に PWDX の社員と照合（externalId で）
```

### UC-06: 入金消込結果のフィードバック

```
[基本フロー]
  1. fina で経理担当が入金消込（請求書 vs 入金）を完了
  2. fina が PWDX API（POST or PATCH）を叩いて
     PWDX 側の請求書ステータスを「入金済」に更新
  3. PWDX 側で案件のステータスが連動して変更（PWDX 側ロジック）

[例外]
  - PWDX 側に POST API が無い → 当面は fina 側でステータス管理、後日仕組み化
```

### UC-07: SSO

詳細は [admin_and_auth_design.md §4.3](./admin_and_auth_design.md) 参照。

```
要求事項:
  - Keycloak Realm pwdx に fina を Client として登録
  - OIDC Authorization Code Flow
  - Claims: sub, pwdx_company_id, pwdx_user_id, name, email（任意）
```

### UC-08: 会社申請時の PWDX 認証取得

詳細は [admin_and_auth_design.md §7](./admin_and_auth_design.md) 参照。

```
要求事項:
  - UC-07 と同じ Keycloak 設定で利用可
  - 申請時の id_token を snapshot として保存
```

### UC-09: 証憑・契約書への参照リンク

```
[基本フロー]
  1. PWDX 内の PDF（契約書・請求書 PDF 等）の URL を fina に伝達
  2. fina の Transaction に externalFileUrl として保存
  3. fina の UI で「契約書を見る」リンクをクリック → PWDX へ遷移

[注意]
  - fina に PDF 本体は持たない（容量・権限の問題）
  - URL アクセス時に PWDX で再認証が必要になるのは許容
```

## 8. 用語と表記の合意

両者で食い違いやすい用語を、本ドキュメント内では次の意味で統一する。

| 用語 | 本ドキュメント内の意味 |
|---|---|
| **会社** | fina の Company（経理単位）。PWDX 側の「会社」と概念は近いが ID 体系は別 |
| **取引先** | fina の TradingPartner。請求書発行先 / 発注先 |
| **取引** | fina の Transaction。実際の出納（資金繰り表に並ぶ 1 行） |
| **請求書** | PWDX で発行する書面。fina では Transaction (SALES) として現れる |
| **発注** | PWDX で確定する仕入の意思表示。fina では Transaction (COST_PAYMENT) として現れる |
| **案件** | PWDX の Project / Job。fina では取引のメモで参照する |
| **社員** | PWDX の Employee。fina では給与計算時に参照 |
| **sub** | Keycloak が発行するユーザー一意 ID（OIDC 標準） |
| **pwdx_company_id** | PWDX 側で会社を一意に識別する ID |
| **pwdx_user_id** | PWDX 側で社員を一意に識別する ID（`sub` と別系統の可能性あり） |

## 9. 未確定の重要論点

PWDX 側と話す前に fina 内部で詰めておきたい論点。

| ID | 論点 | 仮の方針 |
|---|---|---|
| O-1 | 同じ請求書 ID で再取込された時の挙動 | 上書き（最新化）。ただし fina 側で確定済の場合は警告 |
| O-2 | PWDX 側で請求書が取消された場合の fina 側挙動 | fina の Transaction を「取消」ステータスに（物理削除はしない） |
| O-3 | fina で確定済の取引が PWDX 側で更新された場合 | fina 確定後は同期しない（経理データの整合性優先） |
| O-4 | 同期失敗時のリカバリ | SyncJob テーブルで履歴管理。管理画面から再実行 |
| O-5 | PWDX 側にアダプタを置くか fina 側に置くか | 当面は fina 側にアダプタ層を置く（PWDX に手を入れない方針） |
| O-6 | 取引先名の表記揺れ吸収 | fina 側で正規化処理（ふりがな・株式会社の有無等） |
| O-7 | 多通貨対応 | v1 では JPY 固定 |
