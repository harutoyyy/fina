## 🔴 優先度 HIGH（入力導線の根幹・即着手）

### T-01　仮取引先名フィールドの追加
- **影響セクション：** S2 / S3 / S4 / S5 / S9 / S10
- **概要：** `Transaction` モデルに `temporaryVendorName`（文字列・任意）を追加し、`partnerId` が NULL でも保存・準備完了遷移を可能にする。
- **対応内容：**
  - DBスキーマに `temporary_vendor_name` カラムを追加
  - 保存・準備完了バリデーションを「`partnerId` OR `temporaryVendorName` のいずれか必須」に変更
  - 入力フォームに仮取引先名の自由入力欄を追加
  - 一覧表示で仮取引先名を表示（正規取引先との区別表示）
  - 資金繰り表の取引先表示に仮取引先名をフォールバック表示

---

### T-02　`receivedDate`（受領日）フィールドの追加
- **影響セクション：** S3 / S4 / S5 / S8
- **概要：** `Transaction` モデルに `receivedDate`（日付・任意）を追加。証憑添付時に自動セット（手修正可）。
- **対応内容：**
  - DBスキーマに `received_date` カラムを追加
  - 証憑添付アクション時に `receivedDate` を自動セットする処理を追加
  - 入力フォームに受領日表示・手修正欄を追加
  - 受領BOX の対象判定ロジックに受領日条件を組み込む（後述 T-04）

---

### T-03　`evidenceNotRequiredFlag`（証憑なしOK）の追加
- **影響セクション：** S2 / S3 / S4 / S5
- **概要：** `Transaction` モデルに `evidenceNotRequired`（真偽値・デフォルト false）を追加。管理者のみ付与可能。
- **対応内容：**
  - DBスキーマに `evidence_not_required` カラムを追加
  - 管理者UIにフラグ付与操作を追加（OPERATOR ロールからは操作不可）
  - 準備完了バリデーションを「`hasEvidence = true` OR `evidenceNotRequired = true`」に変更
  - 受領BOX フィルタに「証憑なしOK」条件を追加（後述 T-04）

---

### T-04　受領BOX（`/expense-box`）の再設計
- **影響セクション：** S3 / S10
- **概要：** 現状の確定ワークフロー画面を、要件定義の「今日届いた請求書/通知書を潰す」受領BOXに刷新する。
- **対応内容：**
  - 対象明細の出し分けロジックを実装
    - ①証憑が1つ以上添付済み
    - ②受領日が入力済み
    - ③`evidenceNotRequired = true`
  - デフォルト表示を「未準備完了のみ」に変更
  - フィルタUIを追加
    - 受領日（今日 / 今週 / 今月 / 範囲）
    - 証憑あり / 証憑なしOK / 証憑なし（要確認）
    - 取引先（部分一致）
    - 予定日（範囲）
  - 一覧列に受領日・証憑なしOKの表示を追加

---

## 🟡 優先度 MEDIUM（ワークフロー完成度・操作UX）

### T-05　科目列を入力者UIから非表示にする
- **影響セクション：** S1 / S7
- **概要：** OPERATOR ロールでは `/expense-box`・`/expenses` 両画面で科目列（中項目・小項目）を完全非表示にする。
- **対応内容：**
  - ロールに応じた列・操作の出し分けを実装（ADMIN は表示、OPERATOR は非表示）
  - 「⚠ 科目未設定（確定不可）」の状態バッジを OPERATOR 向けに表示

---

### T-06　月締め後の摘要・科目変更と変更ログの実装
- **影響セクション：** S5
- **概要：** 現状は月締め後に一律ロックしているが、要件では摘要・科目の変更は月締め後も許可し、変更ログを残す。
- **対応内容：**
  - `ensureMonthOpen()` ガードを「金額・取消」の変更のみに絞る
  - 月締め後の摘要・科目変更を許可するエンドポイントを追加
  - 変更時に AuditLog へ `UPDATE_AFTER_CLOSE`（変更前後・操作者・日時）を記録

---

### T-07　支払月BOXの「未確定のみ」デフォルト表示と一括「準備完了」の実装
- **影響セクション：** S3
- **概要：** `/expenses` の支払月BOX を要件に合わせて整備する。
- **対応内容：**
  - デフォルト表示を「未確定のみ」に変更（確定表示チェックで混在可能）
  - 並び順を「①実行予定日（昇順）②同日内：取引先順」に変更
  - 複数選択 → 一括「準備完了」処理を実装（証憑は個別必須チェックあり）

---

### T-08　「資金繰り閲覧者」ロールの追加
- **影響セクション：** S2
- **概要：** 要件の3ロール（経費入力者 / 資金繰り閲覧者 / 管理者）を満たすため、`VIEWER` ロールを追加する。
- **対応内容：**
  - `UserProfile` モデルのロール定義に `VIEWER` を追加
  - `VIEWER` に許可する操作：経費明細閲覧・通帳照合点（照合ライン）設定
  - `VIEWER` に禁止する操作：明細の作成・編集・削除・確定・準備完了

---

### T-09　「今月のみ例外」フラグの実装
- **影響セクション：** S6
- **概要：** 入力者が実行予定日を変更した際、次月以降の繰り返し明細に影響させないフラグを実装する。
- **対応内容：**
  - `Transaction` モデルに `isDateException`（真偽値）を追加
  - 入力者が実行予定日を手変更した際に `isDateException = true` を自動セット
  - 繰り返し明細の次月生成ロジックで `isDateException` の明細は原則スキップ

---

## 🟢 優先度 LOW（品質・非機能・電子帳簿保存法対応）

### T-10　証憑の実ファイル保存（S3連携）
- **影響セクション：** S1 / S8 / S12
- **概要：** 現状はモックURL のみ。電子帳簿保存法対応のため S3（または同等のオブジェクトストレージ）への実ファイル保存を実装する。
- **対応内容：**
  - S3 アップロード・署名付きURL取得の実装
  - `Evidence` モデルに S3 キー・バケット情報を保持
  - アップロード・閲覧・削除の各APIを実装

---

### T-11　証憑メタ情報の保持と検索
- **影響セクション：** S8
- **概要：** `Evidence` モデルにメタ情報（取引日・取引先・金額等）を追加し、検索可能にする。
- **対応内容：**
  - `Evidence` モデルに `meta_transaction_date` / `meta_vendor_name` / `meta_amount` 等を追加
  - PDF から自動抽出する仕組みの検討（OCR or 手入力フォールバック）
  - メタ情報による検索クエリを追加

---

### T-12　証憑のプレビュー・サムネイル表示
- **影響セクション：** S8 / S12
- **概要：** 添付ファイルの閲覧応答性を確保する。
- **対応内容：**
  - PDF プレビュー（インライン表示 or モーダル）の実装
  - サムネイル生成または PDF.js によるプレビュー
  - 後日追添付時の「更新ハイライト」表示

---

### T-13　取引先の正規化操作と監査ログの実装
- **影響セクション：** S2 / S11
- **概要：** 仮取引先名 → 正規取引先ID への紐付け操作（T-01 実装後）に対して、操作ログを残す。
- **対応内容：**
  - 管理者向け「取引先正規化」UIを実装
  - 正規化操作時に AuditLog へ `PARTNER_NORMALIZED`（操作者・日時・変更前後）を記録

---

### T-14　ページング / 無限スクロールの実装
- **影響セクション：** S12
- **概要：** 現状は全件取得のため、大量件数でパフォーマンスが劣化する。
- **対応内容：**
  - `/expenses`・`/expense-box` 両画面にページング or 無限スクロールを実装
  - APIにカーソルベースまたはオフセットベースのページネーションを追加
